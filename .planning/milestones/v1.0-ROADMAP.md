# Milestone v1.0: Ground Truth Debug Workflow

**Status:** ✅ SHIPPED 2026-04-12
**Phases:** 1-3
**Total Plans:** 8

## Overview

This milestone turned the maintainer's manual debug loop into a deterministic evaluation workflow. Completed runs now compare against immutable part-level ground truth, auto-pass conforming rows, narrow manual review to exceptions, and preserve accepted alternates in a separate history layer without mutating canonical truth.

## Phases

### Phase 1: Evaluation Foundation

**Goal**: Completed runs can be deterministically compared against immutable part-level ground truth, including tolerant snippet checks that reflect visually acceptable evidence.  
**Depends on**: Nothing (first phase)  
**Plans**: 3 plans

Plans:

- [x] 01-01: Define and validate ground-truth and evaluation contracts
- [x] 01-02: Implement automatic conformance evaluation for classification and requirement matching
- [x] 01-03: Implement tolerant snippet acceptance rules and structured mismatch reasons

**Details:**
Phase 1 established the packet-side evaluation contract. It added strict fixture loading from `assets/{truth_fixture_key}/ground_truth.json`, deterministic requirement comparison, deterministic snippet tolerance, and ordered mismatch codes that downstream review logic can consume directly.

### Phase 2: Focused Debug Workflow

**Goal**: The debug surface and exported report prioritize only nonconforming or ambiguous rows while still preserving visibility into auto-passed results.  
**Depends on**: Phase 1  
**Plans**: 3 plans

Plans:

- [x] 02-01: Rework debug queue state around exception-only review
- [x] 02-02: Extend review/export payloads to represent auto-pass and review-needed outcomes
- [x] 02-03: Update admin debug UX for focused review and rationale capture

**Details:**
Phase 2 re-keyed debug review around packet evaluation status rather than blanket manual verdict entry. The admin experience now uses stable `ReviewItem.id` ordering, redirects all-conforming runs away from an empty queue, exposes explicit debug report row states, and leads reviewers with mismatch-first exception cards plus status-page summaries.

### Phase 3: Exceptions History Layer

**Goal**: Accepted alternate outcomes are stored in a separate history layer and can be reused for later runs of the same part and characteristic without changing canonical truth.  
**Depends on**: Phase 2  
**Plans**: 2 plans

Plans:

- [x] 03-01: Design and persist the exceptions/history model
- [x] 03-02: Integrate history-backed acceptable alternates into evaluation and reports

**Details:**
Phase 3 added durable accepted-alternate persistence, wired verdict saves into history sync, and layered exact same-part alternate reuse on top of canonical truth evaluation. History-backed conformance remains additive and auditable through `conformance_source` and `history_reference`.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Resolve truth fixtures only from `assets/{truth_fixture_key}/ground_truth.json` with no aliasing or fallback.
- Resolve packet rows to `conforming` or `review_needed` before human review so the UI consumes stable evaluation output.
- Use packet order plus `ReviewItem.id` as the debug row identity contract instead of `char_no` sorting.
- Persist accepted alternates in a dedicated history layer and only reuse them for exact same-part, same-fingerprint matches.

**Issues Resolved:**

- Removed the requirement to manually verdict every conforming row in debug review.
- Added deterministic snippet tolerance and ordered mismatch reporting for packet rows.
- Kept canonical matches, unresolved exceptions, and history-backed acceptable alternates distinct in `debug_report.json`.

**Issues Deferred:**

- Phase 1 and Phase 2 verification artifacts were missing at close-out; this was accepted as archived tech debt in the milestone audit.
- Cross-part contradiction detection and benchmark trend analysis remain next-milestone work.

**Technical Debt Incurred:**

- Manual browser verification of the Phase 2 status-page and exception-queue UX was not captured.
- Nyquist validation records remain partial even though the repo-level test suite is green.
