> Per-phase security contract: threat register, accepted risks, and audit trail.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Test route DB -> Huey task DB | The live `/runs/new` proof is only valid when the request path and inline Huey task share the same test database session factory. | `Run`, `ReviewItem`, and task lifecycle state in the test SQLite DB |
| Temp uploads/out roots -> checked-in repo dirs | The Phase 11 live harness must isolate uploaded corpus files and pipeline output so the proof does not contaminate shared repo state. | Uploaded `revA.pdf`, `revB.pdf`, `FAIR.xlsx`, plus generated `delta_packet.json` and snippet/export artifacts |
| Real packet output -> review/debug assertions | The phase claim is only trustworthy if the review and sign-off assertions consume the packet generated by the live run instead of seeded substitutes. | Packet-backed review/debug state and `/review/{run_id}/sign-off/confirm` redirect results |
| Cleared live run -> signed packet version metadata | Signed exports are only valid if sign-off persists a versioned debug snapshot before the run becomes `signed_off`. | `packet_versions[].debug_snapshot_path`, `debug_total`, and `unresolved_exception_count` |
| Seeded companion advisory case -> Phase 11 milestone claim | The advisory fallback must stay explicitly separate from the live corpus proof so the phase does not overstate what the live corpus covers. | Signed snapshot `packet_item.confidence_flags` rendered into export CSV advisory columns |
