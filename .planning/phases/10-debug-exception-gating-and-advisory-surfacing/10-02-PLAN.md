<objective>
Make unresolved debug exceptions enforceable at the real release boundary:
normal review queue sign-off and the sign-off transaction itself.

Purpose: the current review queue only blocks sign-off on pending review
decisions, not on unresolved debug exceptions. Phase 10 must replace that split
contract with one service-level preflight and record the exact debug state that
was cleared at sign-off time.
</objective>

`build_signoff_gate_state(db: Session, run: Run) -> dict` in
`shop/services/review.py`. The helper must combine:

- pending normal review decisions
- unresolved debug exceptions from `build_run_debug_summary()`
- the debug queue target URL (`/review/{run_id}?debug=1`) when exceptions remain

   maintainer to resolve the debug queue first.

   using a distinct error such as `debug_exceptions_pending` rather than
   overloading `pending_items`.

Those tests should prove the gap that exists today: all normal review items are
approved, but one debug exception remains unresolved, and sign-off stays

   `build_signoff_gate_state()`. If the gate is not clear, return a blocked
   result without mutating `run.status`, `signed_at`, or `signed_by_id`.
2. On the success path, capture a versioned signed debug snapshot before
   `run.status` flips to `signed_off`.
   - Use `assemble_debug_report_payload()` as the snapshot source.
   - Persist the snapshot under `output_dir/packets/` with a version-aligned
     filename such as `v{version}-debug-report.json`.
   - Record snapshot metadata on the matching `Run.packet_versions` entry using
     fields such as `debug_snapshot_path`, `debug_total`, and
     `unresolved_exception_count`.

Do not introduce an acknowledgement bypass in this plan. The signed snapshot
must reflect a fully cleared unresolved-debug state.
