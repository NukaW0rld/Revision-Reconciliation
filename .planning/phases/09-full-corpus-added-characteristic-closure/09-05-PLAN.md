<objective>
Close Part 5 truth_index 17 (`3X Ø18 ↧30`) by adding a shared
dimensional-incompatibility guard in `delta_preservation/reconcile/match.py` so
a Rev B candidate cannot claim a Rev A anchor whose primary numeric value is
absent from the candidate's own numeric payload, and so that incompatible
sub-spans are pruned from a grouped candidate's `source_span_keys` before the
match is committed.

Purpose: `09-VERIFICATION.md` and `09-02-SUMMARY.md` both document that the
`3X Ø18 ↧30` callout is not a detector miss — its source spans are already
consumed by char 1 (`Ø35.2 / Ø34.8`) through a grouped-candidate assignment
that would never survive a simple primary-value compatibility check. The fix
belongs in the matching layer, not the detector, because the detector never
sees the spans once `assign_matches` has marked them as used.

This plan is deliberately narrow: it only rejects matches where the candidate
has *no* primary-value overlap with the anchor. Matches that already pass
today's text/location/context scoring are unaffected when the anchor's primary
value is actually present in the candidate or its grouped sub-spans.
</objective>

```python
def _candidate_is_dimensionally_compatible(
    anchor_fp,
    candidate,
    *,
    tolerance: float = 0.05,
) -> bool:
    """Return True when the candidate carries the anchor's primary numeric value.

    Used by assign_matches() to block obvious cross-characteristic mis-assignments
    where a grouped candidate's only numeric payload is dimensionally unrelated to
    the anchor (e.g. an anchor of Ø35.2 / Ø34.8 trying to claim a 3X Ø18 ↧30
    callout that carries no 35.x value anywhere in its source spans).

    The check is intentionally permissive:
      * Anchors with no numeric tokens (notes, pure symbols) are always compatible.
      * Candidates from the global page-wide fallback are always compatible here
        (they already go through the wrong-copy guard).
      * If ANY anchor numeric token appears — within `tolerance` — in the
        candidate's own text OR in any of its `source_spans`, the candidate
        is compatible.  Only candidates with no numeric overlap at all are
        rejected.
    """
```

Implementation rules (the body must follow these rules literally):

- Extract `anchor_numerics = {v for v, _ in anchor_fp.numeric_tokens}`.
  If `not anchor_numerics`, return `True`.
- If `getattr(candidate, "from_global_fallback", False)` is truthy, return
  `True` (preserve existing wrong-copy behaviour; that path has its own guard).
- Parse `candidate.span.text` with `parse_requirement(...)` and collect
  `candidate_numerics = {v for v, _ in candidate_fp.numeric_tokens}`.
- Also union in numerics from every entry in
  `getattr(candidate.span, "source_spans", None) or []`, parsing each
  `src.text` with `parse_requirement(...)` and folding its numeric tokens in.
- If `candidate_numerics` is empty, return `True` (non-numeric
  text-pattern-only candidates are out of scope for this guard; the existing
  `MIN_WEAK_MATCH_SCORE` / `anchor_type_tokens` path already handles them).
- Return `True` if there exists any `a in anchor_numerics` and
  `c in candidate_numerics` with `abs(a - c) <= max(tolerance, tolerance * abs(a))`.
  Otherwise return `False`.

After the Task 1 guard lands, grouped candidates that legitimately match an
anchor may still carry foreign sub-spans inside their `source_span_keys`. When
`assign_matches()` records `used_source_span_keys.update(candidate_source_keys_set)`,
those foreign sub-spans get marked as consumed and become invisible to
`detect_added_characteristics()`. This task prunes the consumed set so only
dimensionally-compatible sub-spans are counted as "used".

In `assign_matches()`, locate the accepted-edge block (currently around lines
1074–1086, starting with `# Accept edge only if both char_no and span are available`).
Replace the unconditional `candidate_source_keys_set = set(candidate.source_span_keys or [span_key])`
construction with the following pruned computation:

```python
        if char_no not in assigned_chars and span_key not in used_spans:
            # Only the sub-spans whose numeric payload is compatible with the
            # anchor should be marked as consumed; foreign sub-spans that were
            # merged by _group_candidate_spans must remain available for
            # detect_added_characteristics() so they can surface as added rows.
            source_spans = getattr(candidate.span, "source_spans", None) or []
            if source_spans and anchor_fp is not None:
                anchor_numerics = {v for v, _ in anchor_fp.numeric_tokens}
                compatible_keys: set = set()
                for src in source_spans:
                    src_fp = parse_requirement(src.text)
                    src_numerics = {v for v, _ in src_fp.numeric_tokens}
                    if (
                        not anchor_numerics
                        or not src_numerics
                        or any(
                            abs(a - c) <= max(0.05, 0.05 * abs(a))
                            for a in anchor_numerics
                            for c in src_numerics
                        )
                    ):
                        compatible_keys.add((
                            src.block_id,
                            src.line_id,
                            src.span_id,
                            src.bbox_pdf,
                        ))
                # If pruning left nothing compatible (all source spans were
                # foreign), fall back to the candidate's own span_key so the
                # match still records its primary span as consumed.
                candidate_source_keys_set = compatible_keys or {span_key}
            else:
                candidate_source_keys_set = set(candidate.source_span_keys or [span_key])

            if candidate_source_keys_set & used_source_span_keys:
                continue
            matches[char_no] = Match(
                char_no=char_no,
                candidate=candidate,
                pred_center_b=None
            )
            assigned_chars.add(char_no)
            used_spans.add(span_key)
            used_source_span_keys.update(candidate_source_keys_set)
```

Do NOT alter the `used_spans` set semantics. The primary span (by `span_key`)
remains consumed — only the grouped source-span-key sharing is narrowed.

Do NOT mutate `candidate.source_span_keys` on the candidate itself; other
scorers may need the full original key list.
