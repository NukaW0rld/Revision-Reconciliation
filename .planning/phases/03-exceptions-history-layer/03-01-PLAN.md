<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin debug verdict POST -> history sync service | Reviewer-entered data crosses from validated form input into durable reusable history records. |
| Packet evaluation row -> stored history snapshot | The sync service derives `matched_truth_char_no` and mismatch fingerprints from file-backed packet data and must not persist the wrong row identity. |
| Durable history table -> future run reuse | Once active, stored alternate outcomes can affect later runs and therefore must be strictly scoped and auditable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | T | `shop/services/alternate_history.py` | mitigate | Build history rows only from `validate_debug_verdict_payload(...)` output plus the packet row for the exact `ReviewItem.id`; reject ad hoc payload fields. |
| T-03-02 | T/R | `accepted_alternate_history` | mitigate | Store `run_id`, `review_item_id`, timestamps, and rationale; deactivate/supersede records when the source verdict changes so stale approvals cannot silently persist. |
| T-03-03 | S/T | future lookup boundary | mitigate | Persist `part_number` and `matched_truth_char_no` now so later lookup can enforce exact same-part, same-truth-identity reuse instead of broad `char_no` matching. |
</threat_model>
