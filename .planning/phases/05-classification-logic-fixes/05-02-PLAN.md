- Add `_BLEED_FLAG = "Rev B text may contain adjacent balloon content"`.
- Add `_BLEED_SPLIT_RE = re.compile(r"\\s+/\\s+")` so the helper only treats whitespace-separated slash chunks as bleed candidates. This avoids `1/8` and `H7/p6`.
- Add `_looks_like_adjacency_bleed(span_text: str, anchor_text: str) -> bool`.

`_looks_like_adjacency_bleed(...)` must:
1. Split with `_BLEED_SPLIT_RE`; return `False` if fewer than 2 chunks.
2. Parse `anchor_text` with `parse_requirement(...)`.
3. Treat a chunk as "anchor-bearing" only if it contains either the anchor's primary numeric token or at least two normalized non-stopword anchor keywords.
4. Treat a different chunk as "foreign-count-bearing" only if it contains a count prefix like `2X` or `4 x` and does not carry the anchor's primary numeric token.
5. Return `True` only when both signals are present in different chunks.

Integrate the helper inside the `if count_changed or count_added:` branch:
- Only run it when `count_added` is true and `count_changed` is false.
- If it returns true, set `status = "unchanged"`, keep a moderate confidence floor such as `max(0.55, ...)`, append a human-readable suppression reason, and append `_BLEED_FLAG` to `confidence_flags`.
- Put the exact phrase in `confidence_flags`. It may also appear in `reasons`, but `confidence_flags` is the authoritative home.
- Leave the existing earlier `count_added and not anchor_numerics` suppressor intact.
