CLS-03: detect a symmetric-to-asymmetric tolerance transition (e.g. `±1°` -> `+0.3° / −0.1°`, or the reverse direction) and reclassify the item as `changed` when the primary-dimension path would otherwise yield `unchanged`. Two defensive paths: (1) primary kind-based check against `ToleranceComparison.revA_tolerance.kind` vs `.revB_tolerance.kind` (uses existing `PdfToleranceKind` literal from `tolerance_pdf.py` — no parser change), (2) string-shape fallback when `tolerance_comparison` is None so unit tests and edge-cases still get covered.

Purpose: Part-7 char-4 (anchor `2X 22.0° ±1°` vs Rev B `2X 22.0° +0.3° / −0.1°`) currently classifies as `unchanged` because the numeric-overlap path matches on `22.0` and the tolerance comparator cannot distinguish structural asymmetry from numeric difference alone. The existing `ToleranceComparison.revA_tolerance.kind` field already captures the distinction (`plus_minus` vs `bilateral_stacked`/`unilateral_stacked`); the classifier just needs to consult it.
Output: two module-level constants, two conditional blocks inside `classify_delta` (one inside `tolerance_comparison is not None`, one in the fallback path), and a populated `TestAsymmetricTolerance` class.
