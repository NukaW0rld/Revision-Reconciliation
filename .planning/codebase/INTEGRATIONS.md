## Data Storage

**Databases:**
- SQLite (file-based)
  - Primary connection: via `DATABASE_URL` env var, defaults to `sqlite:///./shop.db`
  - Client: SQLAlchemy ORM (`shop/database.py`)
  - Location: `/app/data/shop.db` in Docker, `./shop.db` locally
  - Schema: Managed by Alembic migrations (`alembic/` directory)

**Task Queue Storage:**
- SQLite (Huey backend)
  - Path: `HUEY_DB` env var, defaults to `/app/data/huey.db`
  - Purpose: Persists pending and completed background tasks
  - Used by: `shop/tasks.py` (`SqliteHuey(filename=HUEY_DB)`)

**File Storage:**
- Local filesystem only
  - Uploads: `UPLOADS_DIR` env var (default: `/app/data/uploads`)
    - User-supplied Rev A/Rev B PDFs and Form 3 Excel files
  - Pipeline output: `OUT_DIR` env var (default: `/app/out`)
    - JSON delta packets, PNG snippets, debug files generated by reconciliation pipeline
  - Static assets: `static/` directory (CSS, images)

**Caching:**
- None - SQLite doubles as both primary DB and task queue

## Authentication & Identity

**Auth Provider:**
- Custom session-based (no external OAuth/SSO)
  - Implementation: Session tokens stored in SQLite (`sessions` table in `shop/models.py`)
  - Password hashing: Bcrypt via `pwdlib[bcrypt]`
  - Session location: HTTP-only cookie named `session_token`
  - Cookie config (`shop/routers/auth.py` line 49-56):
    - `httponly=True`
    - `samesite="lax"`
    - `secure=False` (comment notes this requires HTTPS terminator in production)
    - `max_age=8*3600` (8-hour expiry)

**User Model:**
- `User` table (`shop/models.py`):
  - username (unique)
  - hashed_password (bcrypt)
  - role: "admin" | "engineer"
  - is_active (boolean)

**Seeding:**
- Default admin user created from env vars on startup (`run_web.py`):
  - `ADMIN_EMAIL` (default: `admin@shop.local`)
  - `ADMIN_DEFAULT_PASSWORD` (default: `changeme`)

## File Format Support

**Input Formats:**
- PDF (`.pdf`) - Rev A and Rev B drawings
  - Parsed via PyMuPDF (fitz)
  - Extracted to: text, images, annotations (balloons), coordinates
- Excel (`.xlsx`, `.xls`) - Form 3 characteristic definitions
  - Parsed via OpenPyXL (`delta_preservation/io/xlsx.py`)

**Output Formats:**
- JSON (`delta_packet.json`) - Reconciliation results, stored in pipeline output directory
  - Schema: `DeltaPacket` and `DeltaItem` types (`delta_preservation/types.py`)
- PNG (`.png`) - Cropped snippet images (Rev A/Rev B characteristic regions)
  - Stored in `output_dir/snippets/` subdirectory
- PDF (`.pdf`) - Audit packet export via WeasyPrint
  - Rendered from Jinja2 template (`shop/templates/exports/audit_packet.html`)
  - Endpoint: `shop/routers/exports.py` `render_audit_packet_pdf()`
- CSV (`.csv`) - Audit packet export for spreadsheet analysis
  - Fields: char_no, requirement_revA/B, classification, reviewer decisions, semantic data
  - Endpoint: `shop/routers/exports.py` `generate_audit_packet_csv()`

## Data Flow

1. **Ingest:** User uploads Rev A PDF, Rev B PDF, Form 3 Excel via web UI
   - Files stored in `UPLOADS_DIR`
   - Run record created in `runs` table with status=`queued`

2. **Queue:** Web API submits `run_pipeline_task()` to Huey task queue

3. **Process:** Huey worker executes pipeline in `delta_preservation/cli.py`:
   - Form 3 parsing → Balloon detection → Text extraction → Alignment → Candidate matching → Classification → Output
   - Updates `Run.current_stage`, `Run.current_stage_index` at each stage
   - On success: `status=completed`, writes `delta_packet.json` and snippets to `output_dir`
   - On failure: `status=failed`, creates `RunAlert` record

4. **Review:** Engineer reviews characteristics in web UI, overrides classifications if needed
   - Review decisions saved to `review_items` table

5. **Export:** Engineer exports audit packet as CSV or PDF for archival/submission
